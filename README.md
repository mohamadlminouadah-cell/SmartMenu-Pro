# SmartMenu Pro — النسخة الأولى

## التشغيل
افتح `index.html` في المتصفح (الواجهة) و`admin.html` (لوحة التحكم). الملفات الستة يجب أن تبقى في نفس المجلد.
لتجربة الهاتف: ارفع المجلد على Netlify أو Vercel أو GitHub Pages (مجانًا)، ثم أنشئ QR من لوحة التحكم برابط الموقع.

## ما يعمل فعليًا
المنيو، البحث، التصنيفات، الإضافات، السلة، حساب الأسعار والخصم والتوصيل والحد الأدنى، رسالة واتساب جاهزة (الرقم يُعدَّل من الإعدادات)، اتصال هاتفي، روابط التواصل، QR، إدارة الوجبات والتصنيفات والإضافات، حالات الطلبات، الإحصائيات، تخصيص الألوان.

## ما لا يعمل بعد (يحتاج خادمًا)
- وصول الطلبات تلقائيًا إلى المطعم: «الإرسال المباشر» يحفظ في متصفح الزبون فقط. الطلب الحقيقي حاليًا عبر واتساب.
- مطاعم متعددة وحسابات وصلاحيات: LocalStorage مناسب للتجربة فقط.
- لوحة التحكم بلا كلمة مرور في هذه النسخة، ولا يجوز وضع كلمات مرور في ملفات JavaScript.
- الإشعارات الفورية.

## الترقية إلى Supabase
كل الوصول للبيانات في `store.js` (`load` / `save`). استبدلهما بنداءات Supabase مع جداول:
`restaurants(id, owner_id, slug, ...)`, `categories`, `items`, `extras`, `orders` وكلها فيها `restaurant_id`.
فعّل Row Level Security: القراءة العامة للوجبات المتاحة، وإنشاء الطلبات للجميع، أما تعديل الوجبات وقراءة الطلبات فلمالك المطعم فقط (`auth.uid() = owner_id`). هكذا لا يصل مطعم إلى بيانات مطعم آخر. يصبح الرابط `index.html?r=slug`.

## تحديث: الطاولات والحسابات والنشر
- **الدخول:** `admin.html` ← «إنشاء مطعم» بمعرّف إنجليزي وكلمة مرور. كل مطعم له بياناته المنفصلة (مفتاح تخزين خاص). كلمة المرور تُخزَّن كملح + PBKDF2 فقط، لكنها حماية محلية في المتصفح وليست أمانًا حقيقيًا عبر الأجهزة.
- **رابط الزبون:** `index.html?r=معرّف-المطعم` وللطاولة `&t=رقم`. الطاولة تظهر في رسالة واتساب وفي الطلب.
- **النشر:** من «الحساب والنشر» حمّل `معرّف.json` وضعه في `data/` بجانب الموقع. بدونه لا يرى الزبون على هاتفه تعديلاتك.
- **للمعاينة قبل النشر:** أضف `&preview=1` للرابط (زر «عرض المنيو» يفعل ذلك).
- **عند البيع لمطاعم كثيرة:** الأفضل Supabase Auth + RLS بدل ملفات JSON.
